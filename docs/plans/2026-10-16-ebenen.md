# Ebenen Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Die Pixelart-PWA bekommt bis zu 16 Ebenen mit Sichtbarkeit, Sperre, Deckkraft, Reihenfolge, Umbenennen, Zusammenführen und vollständigem Undo/Redo.

**Architecture:** `PixelDocument` hält eine Ebenenliste; `doc.get/set/data` und alle Werkzeuge wirken auf die aktive Ebene, das Gesamtbild kommt aus einem gecachten `composite()`. `History` wird zu einer Befehls-History (Pixel-Diffs mit Ebenen-ID plus Struktur-Schritte). Gespeichert wird ein versioniertes Format mit Migration alter Stände; die Oberfläche ist ein Sheet/Seitenfenster per Button.

**Tech Stack:** Vanilla TypeScript, Vite, Vitest (Testumgebung `node`, kein DOM), Canvas 2D, IndexedDB.

**Spec:** `docs/specs/2026-10-16-ebenen-design.md`

## Global Constraints

- `MAX_LAYERS = 16`, mindestens 1 Ebene; Dokumentgröße weiterhin 1..128.
- Deckkraft: ganze Zahl 0..100; Ebenenname höchstens 24 Zeichen, Standard `Ebene N` (N = Ebenen-ID); leerer Name wird ignoriert.
- Ebenen-IDs ab 1, werden nie wiederverwendet (`nextId` wird nie zurückgesetzt).
- Pixel sind `0xRRGGBBAA` in `Uint32Array`, `0` = transparent; Index 0 der Ebenenliste = unterste Ebene.
- Compositing: von unten nach oben, nur sichtbare Ebenen, Source-over mit nicht-prämultipliziertem Alpha, `Math.round` auf ganze Kanäle.
- History-Limit bleibt 100 Schritte; `begin/set/commit/cancel` für Striche bleiben erhalten.
- Gespeichertes Format `version: 2`; Stände ohne `version` werden zu einer Ebene "Ebene 1" migriert.
- UI-Texte deutsch; Touch-Ziele mindestens 40 px; SVG-Icons mit `stroke-width="1.25"`; Ebenen-Vorschau 24×24 px.
- Hochformat: Ebenen-Sheet von unten, höchstens 60 % der Höhe; Querformat: Fenster rechts, 280 px breit.
- Bestehende 19 Tests müssen grün bleiben; nach jedem Task laufen `npx tsc --noEmit` und `npx vitest run` ohne Fehler.

## Review Focus

- Eine gelöschte Ebene wird per Undo mit **derselben ID** und allen Pixeln zurückgeholt; danach angelegte Ebenen bekommen keine bereits vergebene ID (Task 2).
- Zusammenführen mit unterschiedlichen Deckkräften und transparenten Pixeln, samt Undo/Redo (Tasks 1, 2).
- Alter Einzel-Ebenen-Stand ohne `version` lädt; beschädigter Stand (falsche Datenlänge, 0 oder 17 Ebenen) führt zu einem leeren Dokument statt zu einem Absturz (Task 3).
- Deckkraft-Schieber: Ziehen ohne Wertänderung erzeugt keinen History-Schritt; Ziehen mit Änderung genau einen (Task 2).
- Zeichnen auf gesperrter oder ausgeblendeter Ebene ändert nichts, erzeugt keinen Schritt und zeigt einen Hinweis; Ebenenwechsel oder Öffnen der Liste mitten im Strich verwirft den Strich (Tasks 4, 5).

  - `layerActions(doc: PixelDocument): { canAdd; canDuplicate; canRemove; canMoveUp; canMoveDown; canMergeDown }` (alle `boolean`; `canMergeDown` nur wenn aktive Ebene nicht unterste, sichtbar, und die untere nicht gesperrt ist).

### Task 2: Befehls-History für Ebenen

**Files:**
- Modify: `src/model/History.ts`
- Create: `src/model/history.test.ts`

**Interfaces:**
- Consumes: Task 1 (`PixelDocument`, `Layer`, `LayerProps`, `blendOver`, `MAX_LAYERS`, `layerActions`-Logik über `doc`).
- Produces `History` zusätzlich zu `begin/set/commit/cancel/undo/redo/canUndo/canRedo` (unverändert benannt; `set` schreibt in die aktive Ebene, merkt `layerId` aus `begin()` und ruft `doc.touch()`; `undo/redo/cancel` rufen ebenfalls `doc.touch()`):
  - `addLayer(): Layer | null` — `null` bei 16 Ebenen; neue Ebene direkt über der aktiven, wird aktiv.
  - `duplicateLayer(): Layer | null` — Kopie der aktiven (Pixel kopiert, Eigenschaften übernommen, Name `` `${name} Kopie` `` auf 24 gekürzt), direkt darüber, wird aktiv; `null` bei 16.
  - `removeLayer(): boolean` — aktive Ebene; `false` bei nur einer; danach aktiv: Ebene darunter, sonst oberste.
  - `moveActive(delta: 1 | -1): boolean` — `false` am Rand.
  - `mergeDown(): boolean` — aktive in untere: untere Pixel = `blendOver(unten, oben, Deckkraft_oben)` je Pixel; untere behält Name/Deckkraft/Sichtbarkeit/Sperre und wird aktiv; `false` wenn `layerActions(doc).canMergeDown` false.
  - `setProps(id: number, props: Partial<LayerProps>): boolean` — ein Schritt; `false` ohne tatsächliche Änderung.
  - `previewProps(id: number, props: Partial<LayerProps>): void`, `commitProps(): boolean`, `cancelProps(): void` — für Schieber: `previewProps` wendet sofort an und merkt den ersten Ausgangswert, `commitProps` erzeugt genau einen `props`-Schritt oder `false`, wenn Ausgangs- und Endwert gleich sind.
  - Jede neue Aktion leert den Redo-Stack; `setActive` ist kein Schritt.
  - Schrittarten: `pixels` (`layerId`, Liste `{i, before, after}`), `add`, `remove` (volle Ebene inkl. Pixel, Index, vorherige und nachfolgende `activeId`), `move`, `props`, `merge` (obere Ebene voll, Index, Kopie der unteren Pixel vorher, ID der unteren).

- [ ] **Step 1: Failing tests in `src/model/history.test.ts`:**
  - `addLayer`: Undo entfernt die Ebene und stellt die vorherige `activeId` wieder her, Redo fügt dieselbe Ebene (gleiche `id`) wieder ein.
  - `removeLayer`: Pixel der Ebene vorher gesetzt; Undo bringt Ebene mit **gleicher id** und allen Pixeln zurück und aktiviert sie wieder; eine danach angelegte Ebene hat eine neue, noch nie vergebene `id` (nicht die der gelöschten).
  - `Grenzen`: `addLayer()` und `duplicateLayer()` bei 16 Ebenen → `null`, kein History-Schritt (`canUndo` unverändert), kein Fehler; `moveActive(1)` auf der obersten und `moveActive(-1)` auf der untersten Ebene → `false`, kein Schritt.
  - `removeLayer` der letzten Ebene → `false`, kein Schritt; bei der untersten von drei Ebenen wird nach dem Löschen die oberste aktiv.
  - `moveActive` und `duplicateLayer`: Undo/Redo stellen Reihenfolge bzw. Ebenenzahl wieder her; Duplikat hat gleiche Pixel, Name endet auf ` Kopie`.
  - `mergeDown`: untere `0xff0000ff`, obere `0x0000ffff` mit Deckkraft 50 → untere Pixel `0x800080ff`, obere Ebene weg, untere aktiv; Undo stellt beide Ebenen mit ihren ursprünglichen Pixeln wieder her; Redo wiederholt das Ergebnis; `false` bei gesperrter unterer oder ausgeblendeter oberer Ebene.
  - `pixels` mit Ebenenwechsel: Strich auf Ebene A, Strich auf Ebene B, Undo ändert nur B, zweites Undo nur A.
  - `previewProps`: 5× `previewProps(id, {opacity: …})` dann `commitProps()` → genau ein Undo-Schritt, Undo setzt den Ausgangswert; `previewProps` mit Endwert = Ausgangswert → `commitProps()` ist `false`, `canUndo` unverändert.
  - `setProps` ohne Änderung → `false`; mit Änderung → Undo/Redo korrekt; neue Aktion nach Undo leert Redo; Limit 100 bleibt (101 Schritte → ältester entfällt).
  - `begin/set/commit/cancel`: alle bisherigen Tests aus `model.test.ts` bleiben grün.

- [ ] **Step 3: Implement** in `src/model/History.ts`: ein diskriminierter Union-Typ für Schritte, ein gemeinsamer Undo-/Redo-Stack, `apply(step, direction)` je Schrittart über die Primitive aus Task 1 (`insertLayer`, `removeLayer`, `moveLayer`, `setLayerProps`, `setActive`); `pixels`-Schritte werden defensiv übersprungen, wenn die Ebene fehlt.
