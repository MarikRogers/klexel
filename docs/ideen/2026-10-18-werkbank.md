# Werkbank für Spielgrafik (Ideen 1–3)

Stand: 2026-10-18 · Status: Idee · Priorität: hoch · Teil von `2026-10-18-roadmap.md`

Gemeinsamer Baustein: ein **Paletten-Modell** (benannte Palette, optional „gesperrt"), das alle drei Ideen nutzen.

## 1. Direktexport für kleine Konsolen und Engines (PICO-8 zuerst)

- Sprites als fertiger `__gfx__`-Block in eine `.p8`-Datei schreiben bzw. in eine bestehende `.p8` einfügen.
- Auf die 16 PICO-8-Farben beschränken: Palette sperren, 8×8-Raster, Sprite-Nummern anzeigen.
- `.p8`-Sprites wieder importieren.
- Danach: Godot/Tiled/Aseprite-kompatibles JSON zum Spritesheet (baut auf dem vorhandenen Spritesheet-Export auf, siehe `../specs/2026-10-16-animation-design.md`; dort ist die „JSON-Begleitdatei" bisher ausdrücklich ausgeschlossen).
- Kontext: Im Ordner `D:\source\docs` liegen bereits `.p8`-Dateien und `midi2sfx.py`.
- Aufwand: mittel. Passt auf die vorhandenen Export-Module.
- Offene Fragen: Umgang mit Transparenz (PICO-8 hat Farbe 0 als transparent), Zielgröße (128×128 im gfx-Bereich), Verhalten bei mehreren Frames/Ebenen (flach rechnen).

## 2. Foto → Pixelart mit Palette

- Bild importieren, auf 16×16 bis 128×128 verkleinern.
- Auf Palette abbilden: PICO-8, Game Boy, NES, eigene.
- Wahlweise Dithering: Bayer, Floyd-Steinberg.
- Paletten-Import von Lospec (`.hex`, `.gpl`).
- Nutzen: auf dem Handy sofort vorzeigbar und teilbar.
- Aufwand: mittel.
- Offene Fragen: Farbabstand (RGB vs. Lab), Seitenverhältnis/Zuschnitt, Vorschau vor dem Übernehmen.

## 3. Bild-im-Link teilen, ganz ohne Server

- 32×32-Bild mit Palette komprimiert in wenige hundert Zeichen, im URL-Fragment (`#…`), damit nichts an einen Server geht.
- Link öffnet das Bild direkt in Klexel; Empfänger kann es remixen.
- Kein Konto, kein Backend, kein Datenschutzproblem.
- Aufwand: klein bis mittel.
- Offene Fragen: Format (Palette + Indizes, RLE/Deflate, Base64url), Versionsfeld im Format, Größenlimit, Umgang mit Frames/Ebenen (v1: nur flaches Einzelbild).
